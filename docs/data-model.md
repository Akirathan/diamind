# Data model

- mostly inspired by Workflowy
- Terminology
  - _Global root_ - the node with indentation 0. There is exactly one.
  - _Local root_ - the node that is currently zoomed into. It is the top of the visible tree.
- Node
  - Type
    - Text (bullet, paragraph, heading, ...)
    - Attachment (PNG, JPG, PDF, ...)
      - An attachment node only displays the attachment inline
      - Attachment node cannot have both attachment and text.
      - Attachment node still displays the bullet on the left. This is unlike Workflowy, which does not display bullet when you upload a file to a node.
  - Data
    - id
    - parent_id
      - empty for the global root
    - sort_key
      - order between siblings
    - Indentation
      - derived from the chain of parents, not stored.
      - 0 is for the global root
      - can be a positive integer greater than 0.
    - type
    - format
    - note
      - multi-line text below the node text, see [Notes](notes.md).
    - completed_at
      - empty if not completed, see [Completed nodes](completed.md).
    - created_at
    - modified_at
  - format
    - bullet
    - paragraph
    - heading 1
    - heading 2
    - heading 3
    - divider
  - A node can be empty (empty text and empty note). In such case, it will usually be displayed as an empty bullet.
    - The last two children of a node cannot both be empty.
    - Two (or more) empty siblings are allowed if a non-empty sibling follows them.
    - See `Enter` in an empty node in [Node editing](node-editing.md).
  - Indent / Unindent
    - Usually done by hitting `Tab` when cursor is anywhere in the node.
    - Only +-1 level of indentation is allowed for the child node.
  - State
    - UI state, stored per device, separately from the node data. See [Storage](storage.md).
    - Collapse / expand state of the children nodes.
    - Scroll position
  - Attributes
    - An arbitrary key-value map per node.
      - Key: a non-empty string.
      - Value: any JSON value (string, number, boolean, null, array, object).
    - Any node can have attributes, including attachment nodes.
    - For now, only data. No UI for displaying or editing attributes.
    - Later: search by attributes, display of attributes, ...
    - The note and `completed_at` are separate fields, not attributes.
      - They have their own behavior (editing, search, empty rule, merge) and a fixed type.
      - Attributes are for user data, e.g. a due date, a URL or a status.
